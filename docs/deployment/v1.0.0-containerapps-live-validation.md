## Why Container Apps

The Azure subscription `6f6d44e3-...` cannot create any `Microsoft.Web` resources (App Service plans, Functions) due to subscription-wide quota restriction (ExtendedCode 59911). This was verified across 7+ regions and all plan tiers (FC1, Y1, B1, F1). Azure Container Apps was chosen as the live-validation hosting alternative. The intended architecture remains Durable Functions — Container Apps mode is a deployment adapter only.

## Image Architecture Fix

Docker images built on Apple Silicon Macs default to `arm64/linux`. Azure Container Apps runs `amd64` nodes, causing persistent `ImagePullBackOff` errors. Images must be built with:

```bash
docker build --platform linux/amd64 --file backend/Dockerfile -t <acr>/claimpilot-backend:v1.0.0-amd64 .
docker push <acr>/claimpilot-backend:v1.0.0-amd64
```

The Dockerfile was also fixed to remove `COPY domains/` (domains live inside `backend/domains/`).

## Foundry Project

The ARM `Microsoft.CognitiveServices/accounts/projects` API experienced intermittent `InternalServerError` in `swedencentral` during deployment. The foundry module includes a `createProject` parameter (default `true`) to optionally skip project creation. In the devca parameter file, `createProject = false` was set during deployment. The project `claimpilot-devca-project` was eventually created successfully and is in `Succeeded` state.

If the project needs to be recreated, it can be done via:
1. Azure AI Foundry portal under `claimpilot-devca-foundry`
2. ARM deployment with `createProject = true` (may require retries)

Required environment variables for Foundry:
- `AZURE_FOUNDRY_ENDPOINT` — from foundry account
- `AZURE_FOUNDRY_PROJECT_ENDPOINT` — from foundry project
- `FOUNDRY_MODEL_DEPLOYMENT` — model deployment name (e.g., `gpt-5-4`)
- `CLASSIFIER_AGENT_ID`, `EXTRACTOR_AGENT_ID`, `FRAUD_AGENT_ID`, `DECISION_AGENT_ID` — agent IDs after creation

## Known Limitations

1. **Container Apps is not the intended architecture** — Durable Functions remains the target. Container Apps mode exists solely because this subscription cannot create App Service plans.
2. **ACR Tasks blocked** — Same subscription quota issue prevents `az acr build`. Images must be built locally and pushed.
3. **Foundry project ARM intermittent** — `createProject` parameter added as workaround.
4. **AI Search Basic SKU** — `standard` SKU failed due to capacity limits in swedencentral; downgraded to `basic`.
5. **No Foundry agents created** — Agent IDs not deployed. App runs in stub mode (`CLAIMPILOT_USE_STUBS=1`) for validation without real Foundry agents.
6. **Worker exits without Service Bus messages** — The worker polls `claims-ingestion` queue and will exit if no messages arrive. This is expected for idle state.
