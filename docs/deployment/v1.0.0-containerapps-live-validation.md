## Why Container Apps

The Azure subscription `6f6d44e3-...` cannot create any `Microsoft.Web` resources (App Service plans, Functions) due to subscription-wide quota restriction (ExtendedCode 59911). This was verified across 7+ regions and all plan tiers (FC1, Y1, B1, F1). Azure Container Apps was chosen as the live-validation hosting alternative. The intended architecture remains Durable Functions — Container Apps mode is a deployment adapter only.

## Image Architecture Fix

Docker images built on Apple Silicon Macs default to `arm64/linux`. Azure Container Apps runs `amd64` nodes, causing persistent `ImagePullBackOff` errors. Images must be built with:

```bash
docker build --platform linux/amd64 --file backend/Dockerfile -t <acr>/claimpilot-backend:v1.0.0-amd64 .
docker push <acr>/claimpilot-backend:v1.0.0-amd64
```

The Dockerfile was also fixed to remove `COPY domains/` (domains live inside `backend/domains/`).

## Adjuster WebSocket Fix (v1.0.3–v1.0.11)

### Current Mode: Voice Live Active

The live deployment runs in **Voice Live audio mode** with text fallback.

Voice Live configuration:
```
VOICE_LIVE_ENDPOINT=https://claimpilot-devca-foundry.cognitiveservices.azure.com/
VOICE_LIVE_MODEL=gpt-realtime
VOICE_LIVE_API_VERSION=2025-10-01
```

Voice Live connects to `wss://<account>.services.ai.azure.com/voice-live/realtime` with keyless Entra ID auth. Tool definitions use flat format (name at top level, not nested under function).

When `VOICE_LIVE_ENDPOINT` is not set, degrades to text fallback mode automatically.

### Root Cause

The adjuster voice WebSocket (`/api/v1/adjuster/voice/{claim_id}`) failed with close code 1006 (abnormal close). Two issues:

1. **Missing `websockets` library** — `pyproject.toml` listed `uvicorn>=0.32.0` without the `websockets` extra. Uvicorn logged: *"No supported WebSocket library detected"* and returned HTTP 404 for WebSocket upgrade requests.
2. **`VoiceLiveService` had no `ClaimStateStore`** — `ClaimLookupTool()` was created without a state store, so all claim lookups returned `found=False` and the socket closed with 4004.

### Fix Applied

- Added `websockets>=12.0` to `pyproject.toml` dependencies
- Fixed `VoiceLiveService.__init__` to pass `ClaimStateStore()` to `ClaimLookupTool`
- Made WebSocket handler resilient: accept first, fall back to text mode if Voice Live setup fails
- Added `_handle_text_fallback()` for text-based claim queries (fraud score, damage, decision reasoning)
- Updated frontend to handle `status` message type from backend

### Remaining Blockers for APPROVE Path

1. **Content Understanding `multimodalintelligence` API not available** — subscription does not support this API on any CU resource or region. Analyzer `claimpilot-damage-analyzer` cannot be created. Image ingestion fails safely. This is a subscription-level limitation requiring Azure support ticket or subscription upgrade.
2. **gpt-4o rate limits**: S0 tier (20 TPM) — sequential agent calls exceed limits. With retry/backoff, agents retry up to 4 times before escalating. For production, request quota increase at https://aka.ms/oai/quotaincrease.
3. **Doc Intel model**: `prebuilt-layout` extracts text but no structured fields. `prebuilt-document` returns `ModelNotFound` on this resource. May need a custom trained model or different resource configuration.

## Rate-Limit Retry/Backoff (v1.0.21)

### Changes

- **`backend/agents/base.py`**: `_call_foundry()` retries on `RateLimitError` (429) with exponential backoff (3 retries, 5s base delay doubling). After exhaustion, raises `AgentResponseError("Agent unavailable due to rate limit after 4 attempts")`.
- **All 4 agents** (classifier, extractor, fraud, decision): In live mode (`use_stub_agents=False`), `AgentResponseError` propagates up instead of silently falling back to stubs.
- **`backend/pipeline/orchestrator.py`**: Catches `AgentResponseError` and marks claims ESCALATED (not FAILED). Other exceptions still mark FAILED.
- **8 new tests**: retry succeeds, retry exhausted, 4 agent live-mode no-fallback, pipeline ESCALATED on agent error.

## Known Limitations

1. **Container Apps is not the intended architecture** — Durable Functions remains the target. Container Apps mode exists solely because this subscription cannot create App Service plans.
2. **ACR Tasks blocked** — Same subscription quota issue prevents `az acr build`. Images must be built locally and pushed.
3. **Foundry project ARM intermittent** — `createProject` parameter added as workaround.
4. **AI Search Basic SKU** — `standard` SKU failed due to capacity limits in swedencentral; downgraded to `basic`.
5. **S0 rate limits** — Sequential agent calls (4 per claim) may exceed S0 rate limits for gpt-4o (20 TPM). With v1.0.21, agents retry with exponential backoff (3 retries) before escalating. No silent stub fallback in live mode. For production, request quota increase.
6. **Worker exits without Service Bus messages** — The worker polls `claims-ingestion` queue and will exit if no messages arrive. This is expected for idle state.
