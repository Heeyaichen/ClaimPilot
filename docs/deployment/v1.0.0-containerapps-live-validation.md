## Why Container Apps

This was verified across 7+ regions and all plan tiers (FC1, Y1, B1, F1). Azure Container Apps was chosen as the live-validation hosting alternative. The intended architecture remains Durable Functions — Container Apps mode is a deployment adapter only.

## Image Architecture Fix

Docker images built on Apple Silicon Macs default to `arm64/linux`. Azure Container Apps runs `amd64` nodes, causing persistent `ImagePullBackOff` errors. Images must be built with:

```bash
docker build --platform linux/amd64 --file backend/Dockerfile -t <acr>/claimpilot-backend:v1.0.0-amd64 .
docker push <acr>/claimpilot-backend:v1.0.0-amd64
```

The Dockerfile was also fixed to remove `COPY domains/` (domains live inside `backend/domains/`).

## Adjuster WebSocket Fix (v1.0.3–v1.0.4)

### Root Cause

The adjuster voice WebSocket (`/api/v1/adjuster/voice/{claim_id}`) failed with close code 1006 (abnormal close). Two issues:

1. **Missing `websockets` library** — `pyproject.toml` listed `uvicorn>=0.32.0` without the `websockets` extra. Uvicorn logged: *"No supported WebSocket library detected"* and returned HTTP 404 for WebSocket upgrade requests.
2. **`VoiceLiveService` had no `ClaimStateStore`** — `ClaimLookupTool()` was created without a state store, so all claim lookups returned `found=False` and the socket closed with 4004.

### Fix Applied

- Added `websockets>=12.0` to `pyproject.toml` dependencies
- Fixed `VoiceLiveService.__init__` to pass `ClaimStateStore()` to `ClaimLookupTool`
- Made WebSocket handler resilient: accept first, fall back to text mode if Voice Live setup fails
- Added `_handle_text_fallback()` for text-based claim queries (fraud score, damage, decision reasoning)
- Updated frontend to handle `status` message type from backend

Result: WebSocket connected, received `session.config`, sent text query, received fraud score response.

## Known Limitations

1. **Container Apps is not the intended architecture** — Durable Functions remains the target. Container Apps mode exists solely because this subscription cannot create App Service plans.
2. **ACR Tasks blocked** — Same subscription quota issue prevents `az acr build`. Images must be built locally and pushed.
3. **Foundry project ARM intermittent** — `createProject` parameter added as workaround.
4. **AI Search Basic SKU** — `standard` SKU failed due to capacity limits in swedencentral; downgraded to `basic`.
5. **S0 rate limits** — Sequential agent calls (4 per claim) may exceed S0 rate limits for gpt-4o (20 TPM). Some agents fall back to stubs under load. Increase rate limit or use higher tier for production.
6. **Worker exits without Service Bus messages** — The worker polls `claims-ingestion` queue and will exit if no messages arrive. This is expected for idle state.
